## Изменения и предложение по конфигурации

- Основной адаптер Авито получает все направления без `avito.directions`; для 15 карточек ML/DS извлекает JSON-LD `description`, `datePosted` и `validThrough`. Истечение валидной даты `validThrough` помечает карточку `closed`. Нормальный поиск помечается UI-статусом `bounded`; ошибка отдельной detail-страницы оставляет список вакансий и помечает результат `partial`.
- RWB использует публичный v2 API и пагинацию по `offset`; для ML/DS карточек ограниченно (до 25, concurrency 4) получает v2 detail с `description`, `requirements`, `experience_type_title`, `is_active` и `is_public`. `availability` вычисляется по двум API-флагам; без них остаётся `unknown`. Карточки агрегируются как `targetEmployer: "Wildberries"`. Если во время чтения каталог меняется, страница не получена, detail неполон, встречена пустая страница или достигнут лимит, адаптер возвращает уже полученные карточки с меткой `partial`, а не теряет весь результат. Нормальный обход получает UI-статус `bounded`.
- Программа Авито Start оформлена переносимым примером в `examples/sources/avito_start.mjs`; пользовательский `sources.local/avito_start.mjs` — тонкий re-export.
- В пользовательской конфигурации предлагается включить `avito: true`, `rwb: true`, `avito_start: true`, если нужны отдельные статусы программ. Для основного Авито и RWB не задавать не подтверждённые справочники направлений. Ozon закрывать адресным HH-поиском, не прямым адаптером.

## Проверка кода

`node --test test/marketplaces-recovery.test.mjs` — 8 тестов прошли. Проверены полный список Авито, JSON-LD детали и истечение `validThrough`, RWB v2 пагинация и detail enrichment, mapping активности/требований, сохранение карточек при сбое страницы и смене total, а также закрытая программа Авито. `node --check` прошёл для обоих адаптеров и примера. Live dry-run вызывал только функции источников; отправок уведомлений и записей в `data/` не было.
